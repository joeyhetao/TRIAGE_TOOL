# LLM 功能使用指南

本指南说明如何为仿真日志分类分诊工具配置并使用 AI 辅助功能。

---

## 一、快速上手（2 步）

### 第 1 步：配置 LLM（界面操作，无需手动编辑文件）

1. 启动工具，点击顶部导航的 **🤖 AI 功能** Tab（始终可见）
2. 在配置表单中填写：
   - **Endpoint**：LLM 服务地址（如 `http://10.0.0.1:8080/v1/chat/completions`）
   - **API Key**：密钥，内网无鉴权留空
   - **模型名称**：与服务端一致（如 `qwen-max`、`GLM-4.7`）
3. 点击 **💾 保存配置** — 自动创建 `llm_config.json`，无需手动操作

> 也可手动创建 `llm_config.json`（与 `triage_tool.exe` 同目录），见本文末尾示例。

### 第 2 步：验证连接

点击 **🔌 连接测试**，看到 `✅ 连接成功  模型：xxx  延迟：230 ms` 即配置成功，AI 功能自动激活。

## 二、增强版 / 基础版模式

工具支持两种运行模式，可随时一键切换：

| 模式 | 说明 |
|---|---|
| **🤖 增强版**（默认）| 显示所有 AI 按钮，使用 LLM 辅助功能 |
| **📋 基础版** | 隐藏所有 AI 元素，与纯规则版完全一致 |

**切换方式**：
- `index.html`：AI 功能 Tab 右上角的 **🤖 增强版** 按钮
- `result.html`（结果页）：顶栏右侧的 **🤖 增强版** 按钮

模式选择保存到浏览器本地（刷新后保留）。

**自动提示切换**：P1/P3 等 AI 功能调用失败时，页面顶部出现黄色提示条，建议切换到基础版继续手工操作。

## 三、配置文件字段说明

### 必填字段

| 字段 | 说明 | 示例 |
|---|---|---|
| `endpoint` | LLM 服务地址。OpenAI 兼容格式以 `/v1/chat/completions` 结尾；Anthropic 格式填 base URL 即可（自动补全） | `http://10.0.0.1:8080/v1/chat/completions` |
| `api_key` | API 密钥，内网无鉴权填 `""` | `"sk-xxxxxxxxxxxx"` |
| `model` | 模型名称，需与服务端一致 | `"qwen-max"` / `"GLM-4.7"` |

### 常用可选字段

| 字段 | 默认值 | 说明 |
|---|---|---|
| `timeout` | `30` | 单次请求超时秒数，大模型响应慢时建议设 60~120 |
| `context_window` | `100000` | 模型上下文 token 数（128K 模型填 128000，1M 模型填 1000000） |
| `p3_max_lines` | `2500` | P2 日志问答每次最多提取的日志行数（随 context_window 自动建议值；字段名 `p3_*` 为遗留命名）|
| `cache_ttl` | `3600` | 相同请求的缓存时间（秒），`0` 禁用 |
| `llm_max_retries` | `2` | 失败时最大重试次数 |
| `llm_retry_delay` | `1` | 首次重试等待秒数（指数退避）|

### P6 知识库检查专用字段

| 字段 | 默认值 | 说明 |
|---|---|---|
| `kb_review_window_size` | `20` | 快速模式：滑动窗口大小（每批条目数）|
| `kb_review_step_size` | `10` | 快速模式：窗口步长 |
| `kb_review_batch_size` | `50` | 深度模式：每批条目数 |

### 不同模型的推荐配置

| 模型上下文 | `context_window` | `p3_max_lines` | `timeout` |
|---|---|---|---|
| 32K（较小模型）| `32000` | `600` | `30` |
| 128K | `128000` | `2500` | `60` |
| 1M | `1000000` | `20000` | `120` |

## 四、各 AI 功能说明

### P0 — 配置管理（AI 功能 Tab）

**未配置态**（`llm_config.json` 不存在或 endpoint/model 为空）：
- 显示完整配置表单，可直接填写并保存
- P5/P6 功能区显示「请先配置 LLM」灰色提示

**已配置态**：
- 折叠显示当前模型名称
- 提供修改配置、连接测试、重载配置文件三个操作

| 操作 | 功能 |
|---|---|
| 💾 保存配置 | 将表单内容写入 `llm_config.json` 并立即生效 |
| 🔌 连接测试 | 发送最小请求验证端点/密钥/模型，显示延迟和模型回复 |
| 🔄 重载配置文件 | 手动修改 `llm_config.json` 后点此生效，无需重启 |

**连接失败常见原因**：

| 错误提示 | 排查方向 |
|---|---|
| `LLM 未配置` | endpoint 或 model 为空 |
| `Connection refused` | endpoint 地址/端口错误，服务未启动 |
| `401 Unauthorized` | api_key 错误 |
| `404 Not Found` | endpoint 路径错误；Anthropic 格式会自动追加 `/v1/messages` |
| `模型名不对` / `400` | model 字段与服务端不一致（注意连字符：`GLM-4.7` 非 `GLM_4.7`）|
| `超时` | 增大 `timeout` 值 |

---

### P1 — 多条命中智能推荐（分析结果页）

**入口**：分析结果页 → 命中 **2 条及以上**知识库条目的错误块 → **🤖 智能推荐**

**功能**：AI 按相关度重排候选条目，每条显示推荐理由，并给出建议优先回归验证的用例列表。

---

### P2 — AI 日志问答（分析结果页顶栏）

**入口**：分析结果页右上角 → **📋 AI日志问答**（仅**路径模式**分析后可见）

**功能**：以自然语言对当前日志提问，支持多轮对话。AI 自动定位日志中最相关的连续片段，所有结论标注原始行号。

**使用示例**：
```
列出所有 UVM_ERROR 的错误ID和发生时间
前 2 个 uvm_error 发生了什么
第 45000 行附近发生了什么
统计各模块的报错次数
```

**注意**：
- 仅**路径模式**可用（上传模式文件分析后立即删除）
- 查询包含「前N个 / 第一 / first / top」时，自动从文件开头定位（不用密度最高区）
- 点「清空对话」重置多轮历史
- 可在查询中指定行号范围：`「行号 45000-47000」`

---

### P3 — 查找相似错误（分析结果页）

**入口**：分析结果页 → 未匹配错误的回写表单下方 → **🔍 查找相似错误**

**功能**：从知识库中找出根因相似的已有条目（最多5条），供填写回写表单时参考。

---

### P4 — 批量错误模式分析（分析结果页顶栏）

**入口**：分析结果页顶栏 → **🤖 AI 模式分析**（仅**多文件**分析后可见）

**功能**：AI 对所有失败文件的错误按根因归纳 3~7 个主要失败模式，每个模式包含：模式标题、涉及错误ID、影响文件数、特征说明、建议排查方向。

---

### P5 — 语义知识库搜索（AI 功能 Tab）

**入口**：AI 功能 Tab → 语义知识库查询区 → 输入描述 → **🤖 语义搜索**

**功能**：用自然语言描述问题，AI 按语义相关度重排结果，找到关键词不同但根因相似的条目。

**与普通搜索的区别**：
- 普通搜索：`超时` 只匹配包含"超时"的条目
- 语义搜索：`超时` 可匹配"transaction 长时间无响应"、"握手无法完成"等语义相近条目

**结果展示**：展示完整条目（全部10个字段），前5条默认展开，支持全部展开/折叠。

**使用示例**：
```
时钟复位后数据通路出现延迟违例
AXI 总线握手超时导致 transaction 丢失
```

---

### P6 — 知识库质量检查 + AI 辅助合并（AI 功能 Tab）

**入口**：AI 功能 Tab → 知识库质量检查区

**功能**：扫描整个知识库，找出描述同一根因的重复或高度相似条目；发现后可直接在界面中 AI 辅助合并。

**两种检查模式**：

| 模式 | 适用场景 | 速度 |
|---|---|---|
| 快速模式（滑动窗口）| 知识库条目较多（>200 条）| 快 |
| 深度模式（全量对比）| 条目较少（<200 条）或需彻底排查 | 慢 |

**操作步骤**：
1. 选择模式，点 **🔬 开始检查**
2. 状态栏显示实时进度（当前处理的错误类型、已发现对数）
3. 检查完成后展示所有疑似重复对（每对展示完整的10个字段对比）

**AI 辅助合并**（每对重复条目均提供）：
1. 点击 **🔀 AI辅助合并** 按钮
2. 弹出 Merge Modal：三列对比表格（条目A | AI建议合并结果 | 条目B）
3. 中间列可直接编辑（AI 预填，关键词/关联用例自动合并去重，详细内容优先）
4. 点 **✅ 确认合并**：条目A 更新为合并结果，条目B 删除
5. 卡片从列表隐藏

> 误删可在8秒内撤销（知识库 Tab 中会显示撤销 Toast）。
>
> 也可点 **⬇ 导出Excel** 导出检查报告，在 Excel 中手动处理后通过知识库 Tab 操作。

## 五、常见问题

**Q：配置文件放在哪里？**
A：和 `triage_tool.exe` 同目录。从源码运行时放 `app.py` 同目录。推荐直接在 AI 功能 Tab 中填写保存，无需手动创建文件。

**Q：修改配置后不重启能生效吗？**
A：可以。在 AI 功能 Tab 点 **🔄 重载配置文件** 即时生效。

**Q：P2 日志问答按钮找不到？**
A：需满足两个条件：① LLM 已配置；② 使用**路径模式**（指定服务器路径）分析。满足后结果页右上角出现「📋 AI日志问答」按钮。

**Q：使用智谱 GLM 等 Anthropic 兼容接口怎么配？**
A：endpoint 填 base URL（如 `https://open.bigmodel.cn/api/anthropic`），工具自动检测格式并追加 `/v1/messages`。模型名注意用连字符：`GLM-4.7`（非 `GLM_4.7`）。

**Q：内网没有外网访问，能用吗？**
A：完全支持。填内网 LLM 服务地址即可，工具不访问任何外部网络，且内置代理绕过（避免系统 http_proxy 干扰内网调用）。

**Q：token 不够用（P2 日志提取太少）？**
A：增大 `context_window` 和 `p3_max_lines`。1M token 模型可设 `"p3_max_lines": 20000`，几乎覆盖完整回归日志。

**Q：P5 语义搜索返回"无相关条目"？**
A：AI 判断为全不相关时会明确返回空，而非强制排序所有候选。这是预期行为。可换更通用的描述词再试。

## 六、完整配置示例

### 内网 OpenAI 兼容服务（128K 模型，推荐）

```json
{
  "endpoint":           "http://10.0.0.1:8080/v1/chat/completions",
  "api_key":            "your-api-key",
  "model":              "qwen-max",
  "timeout":            60,
  "context_window":     128000,
  "p3_max_lines":       2500,
  "p3_chars_per_token": 4,
  "cache_ttl":          3600,
  "llm_max_retries":    2,
  "llm_retry_delay":    1
}
```

### 1M 超大上下文模型

```json
{
  "endpoint":           "http://10.0.0.1:8080/v1/chat/completions",
  "api_key":            "your-api-key",
  "model":              "your-1m-model",
  "timeout":            120,
  "context_window":     1000000,
  "p3_max_lines":       20000,
  "p3_chars_per_token": 4,
  "cache_ttl":          3600,
  "llm_max_retries":    2,
  "llm_retry_delay":    2
}
```

### 内网无鉴权服务

```json
{
  "endpoint":       "http://llm-internal.company.com/v1/chat/completions",
  "api_key":        "",
  "model":          "internal-model-name",
  "timeout":        30,
  "context_window": 100000,
  "p3_max_lines":   2500
}
```

### 智谱 GLM（Anthropic 兼容格式）

```json
{
  "endpoint":       "https://open.bigmodel.cn/api/anthropic",
  "api_key":        "your-bigmodel-api-key",
  "model":          "GLM-4.7",
  "timeout":        60,
  "context_window": 128000,
  "p3_max_lines":   2500
}
```

> endpoint 无需手动添加 `/v1/messages`，工具自动补全。
